# بات سیگنال XT — استراتژی برخورد قیمت با SMA 64 (تایم‌فریم ۱ دقیقه)

فقط داده عمومی XT را می‌خواند و سیگنال **آزمایشی (Paper)** به تلگرام می‌فرستد. هیچ سفارشی ثبت نمی‌کند و API Key صرافی نمی‌خواهد.

## ⚠️ دو واقعیت مهم قبل از شروع
1. **هزینه معامله روی ۱ دقیقه بسیار سنگین است.** حد ضرر روی کندل ۱ دقیقه‌ای معمولاً حدود ۰.۰۳ تا ۰.۱ درصد قیمت است، ولی کارمزد و اسلیپیج رفت‌وبرگشت حدود ۰.۱۸ درصد فرض شده. یعنی ممکن است هزینه چند برابر ریسک (R) شود. بات این setupها را رد می‌کند و تعدادشان را در گزارش می‌نویسد. **احتمال زیاد است نتیجه آموزش «تأیید نشد» باشد؛ این رد شدن درست و صادقانه است، نه خطا.** در این حالت هیچ سیگنال زنده‌ای ارسال نمی‌شود.
2. **GitHub Actions برای ۱ دقیقه‌ای دقیق نیست.** زمان‌بندی (cron) حداقل هر ۵ دقیقه ممکن است و عملاً با تأخیر و گاهی جاافتادگی اجرا می‌شود. راه‌حل این پروژه: هر اجرا آخرین ~۶.۵ ساعت کندل بسته‌شده را بررسی می‌کند (جاافتادگی برخورد نداریم) و سیگنال‌های قدیمی‌تر از ۲۰ دقیقه یا سیگنالی که قیمتش بیش از ۰.۵R جابه‌جا شده را ارسال نمی‌کند. برای پایش واقعاً دقیقه‌به‌دقیقه حالت `live` هست (پایین‌تر).

## تعریف برچسب‌ها
هر برخورد = کندل لمس‌کننده SMA64 که کندل قبلی‌اش کاملاً یک طرف SMA بوده. کندل بعدی «کندل واکنشی» است و سیگنال بعد از **بسته شدن** آن صادر می‌شود. ورود: قیمت بسته‌شدن کندل واکنشی؛ حد ضرر: بیرون سایه کندل‌ها + ۰.۱ATR (حداقل ۰.۸ATR)؛ هدف اول ۲R؛ هدف دوم ۳R (فقط اطلاعاتی؛ در Paper کل پوزیشن در هدف اول بسته می‌شود). افق حداکثر ۶۰ کندل.
- **برگشت معتبر:** هدف قبل از حد ضرر لمس شد.
- **برگشت ضعیف:** تا ۶۰ کندل نه هدف نه حد ضرر.
- **شکست واقعی:** حد ضرر خورد و قبلش حداقل ۳ کندل پیاپی آن سوی SMA بسته شد.
- **شکست کاذب:** حد ضرر خورد ولی شکست پایدار نبود.
- **بدون موقعیت:** کندل واکنشی تأییدکننده نبود، یا هزینه بیش از ۰.۳۵R بود.
- اگر حد ضرر و هدف در یک کندل ۱ دقیقه‌ای بودند (ریزتر از ۱ دقیقه داده نیست): محافظه‌کارانه «ضرر» حساب می‌شود و در گزارش شمارش می‌شود.

## راه‌اندازی با آیفون (قدم‌به‌قدم)
### ۱) ساخت ربات تلگرام
در تلگرام به `@BotFather` پیام بده ← `/newbot` ← نام و username بساز ← **توکن** را کپی کن (محرمانه). سپس ربات خودت را باز کن و `/start` بزن.

### ۲) گرفتن Chat ID
در Safari این آدرس را باز کن (به‌جای TOKEN توکن خودت): `https://api.telegram.org/botTOKEN/getUpdates` ← عدد `"chat":{"id":...}` را یادداشت کن. اگر خالی بود یک پیام دیگر به ربات بده و صفحه را Refresh کن.

### ۳) ساخت Repository
github.com ← ورود ← `+` بالای صفحه ← `New repository` ← نام: `xt-sma64-bot` ← `Create repository`.
- **Private** (اگر خصوصی بسازی): فقط ۲۰۰۰ دقیقه رایگان در ماه داری. اجرای هر ۱۰ دقیقه حدود ۴۳۰۰ اجرای کوتاه در ماه است و ممکن است سهمیه را تمام کند. اگر سهمیه تمام شد اجراها متوقف می‌شوند.
- **Public:** Actions نامحدود و رایگان است ولی فایل‌های `data/` (سیگنال‌ها و گزارش‌ها) برای همه قابل مشاهده است. Secretها (توکن) در هر دو حالت پنهان می‌مانند. انتخاب با خودت.

### ۴) آپلود فایل‌ها
۱. ZIP را در برنامه Files آیفون باز کن تا استخراج شود.
۲. در Repository: `Add file` ← `Upload files` ← همه فایل‌ها و پوشه‌های داخل `xt_adaptive_signal_bot` را انتخاب و آپلود کن ← `Commit changes`.
۳. **قدیمی‌ها:** اگر نسخه قبلی را آپلود کرده بودی، `bot.py` و `requirements.txt` جایگزین می‌شوند (همان نام). پوشه `data/` قدیمی (`model.json`، `state.json`، `signals.jsonl`) را حذف کن: روی فایل ← `⋯` ← `Delete file` ← Commit.
۴. **اگر آیفون پوشه `.github` را آپلود نکرد:** `Add file` ← `Create new file` ← نام را دقیقاً `.github/workflows/bot.yml` بنویس (با تایپ `/` پوشه ساخته می‌شود) ← محتوای فایل `workflow_copy.txt` را کپی/پیست کن ← Commit. پوشه‌های `xt_bot` و `tests` را هم باید با همین روش «Create new file» فایل به فایل بسازی اگر آپلود پوشه کار نکرد (مثلاً `xt_bot/data.py`). آسان‌تر: از Safari حالت `Request Desktop Website` را فعال کن یا از یک کامپیوتر آپلود کن.

### ۵) Secretها
Repository ← `Settings` ← `Secrets and variables` ← `Actions` ← `New repository secret`:
- Name: `TELEGRAM_BOT_TOKEN` — مقدار: توکن BotFather
- Name: `TELEGRAM_CHAT_ID` — مقدار: عدد چت

### ۶) اجازه نوشتن Workflow
`Settings` ← `Actions` ← `General` ← پایین صفحه `Workflow permissions` ← `Read and write permissions` ← `Save`.

### ۷) اجرای تست‌ها به ترتیب (تب `Actions` ← `XT SMA64 Signal Bot` ← `Run workflow`)
۱. mode = `selftest` ← باید سبز شود (تست‌های کد).
۲. mode = `check` ← باید سبز شود و پیام «✅ تست اتصال» به تلگرام برسد. در لاگ برای هر نماد `candles=... missing=... coverage=...` را ببین. **این اولین تست واقعی ارتباط با XT است؛ من نتوانستم انجامش بدهم.** اگر قرمز شد، لاگ را باز کن (۱۲) و متن خطا را برای من بفرست.
۳. mode = `train` ← حدود ۱۵ تا ۴۰ دقیقه (دانلود ۶ ماه داده ۱ دقیقه‌ای ۵ نماد). موفق بودن یعنی: اجرا سبز شود، گزارش فارسی به تلگرام برسد، و فایل `data/report_fa.md` و `data/model_meta.json` ساخته شود. در `model_meta.json` مقدار `approved` را ببین: `true` = تأیید، `false` = رد (دلایل در `reasons` و در پیام تلگرام). **هرگز آن را دستی true نکن.**

### ۸) فعال‌سازی اجرای زنده
فقط اگر `approved` برابر `true` بود: Workflow خودکار است (هر ۱۰ دقیقه `scan` و هر یکشنبه آموزش مجدد). اگر خواستی دستی هم یک اسکن بزنی: `Run workflow` ← `scan`.
پایش واقعاً دقیقه‌ای: `Run workflow` ← mode=`live` (حدود ۵ ساعت اجرا می‌شود و تمام می‌شود؛ باید دوباره بزنی). این حالت دقیقه‌های Actions را زیاد مصرف می‌کند و فقط برای Repository عمومی منطقی است. برای ۲۴ ساعته پایدار بدون هزینه، فقط سرور خودت یا سرویس‌های ابری با پلن رایگان دائمی (که نیاز به کارت/ثبت‌نام دارند) مناسب است: `python bot.py live`.

### ۹) محدودیت‌های ریسک
بات خودش سیگنال را متوقف می‌کند اگر ضرر روزانه ≥ ۱.۵٪ یا Drawdown ≥ ۶٪ شود، و پیام وضعیت می‌فرستد. حداکثر ۳ پوزیشن هم‌زمان و هر نماد یک پوزیشن.

### ۱۰) دریافت گزارش بک‌تست
خودکار در تلگرام پس از `train`. نسخه کامل: Repository ← پوشه `data` ← `report_fa.md`.

### ۱۱) خطایابی
تب `Actions` ← روی اجرای قرمز ← `run-bot` ← مرحله `Run bot` ← متن خطا. موارد رایج:
- `Telegram secrets are missing`: نام Secretها را دقیقاً مطابق بالا بساز.
- `XT kline request failed`/`Unexpected XT kline schema`: آدرس یا فرمت API XT با آنچه کد انتظار دارد فرق دارد؛ متن خطا را برای اصلاح بفرست.
- `Permission denied` هنگام push: مرحله ۶ را انجام بده.
- «No approved model»: مدل تأیید نشده؛ رفتار عمدی است.
